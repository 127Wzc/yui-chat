# 指令资料完整度评分

资料完整度用于确定整理、上游优化或手动排除的优先级，不代表召回准确率、用途真实性或指令执行成功。列表、低分/高分排序及 `command_audit` 工具共用规则 `command-completeness-v3`，不调用模型。

## 总分与扣分明细

从 100 分扣除五个维度的扣分和长正则扣分，再应用确定严重问题的分数上限，最低为零。

| 维度 | 最高扣分 |
| --- | ---: |
| A：检索适用性 | 20 |
| B：字段与事实一致性 | 20 |
| C：标题与指令表达 | 15 |
| D：用途、参数与正文质量 | 25 |
| E：示例可靠性与一致性 | 20 |
| 长正则负担 | 额外 5 |

每条明细包含维度、实际扣分值、字段、原因和建议。同一错误不按每个示例或每个副本反复处罚，每个维度扣到零为止；达到严重问题上限时另外说明上限原因。待核实内容符合诚实整理要求，但仍缺少已确认资料，不能获得对应项目的满分。

建议 90–100 分查看剩余优化项，75–89 分安排优化，60–74 分优先整理，低于 60 分重点核查并考虑手动排除。低分不会自动改变检索启停。

## A：检索适用性

以下源规则判断取最严重的一项，缺少事件信息可另扣，维度总扣分最多 20。

| 问题 | 扣分 |
| --- | ---: |
| 明确永不匹配：原正则精确为 `(?!)`、`((?!))` | 20 |
| 原正则或 flags 无法编译 | 15 |
| 普通 `message` 或其子事件使用已知的全通配/宽泛监听结构 | 10 |
| 规则形似 `名称-plugin-名称-数字` 的内部动态标识，尚无充分证据 | 5 |
| 未提供事件信息 | 5 |

宽泛监听表示缺少独立触发条件，不等于插件无用。`notice`、`request`、`meta_event` 及其子事件主要由事件类型定位，不因空匹配或宽泛正则扣分。事件信息为空时不擅自当成非文本事件。

## B：字段结构与采集事实

正文使用插件名称、插件标识、指令、用途、参数、示例；priority、regexp、regexpFlags 只保存在元数据。必要时可追加权限、别名、前置条件和可信状态。“示例”可重复多行，其余各出现一次。

- 插件名称、插件标识缺失或与元数据不一致，每项扣 2 分；旧正文仍有 priority、regexp、regexpFlags 时检查其值，缺失这些运行字段不扣分。
- 非示例字段重复，每类扣 1 分，最多 3 分。
- 已知字段顺序不规范扣 2 分。
- 额外/旧格式字段每类扣 1 分，最多 3 分；权限、别名、前置条件、可信状态属于允许的可选字段。
- 开头无法归入字段的游离内容扣 2 分。

指令、用途、参数、示例的缺失在对应内容维度扣分，不再按结构缺失重复扣。正则不重复反转义，保留原值及有意义的空白；多行原正则中的标签、URL 和待核实字样不作为说明字段。flags 支持采集器的 JSON 字符串表示，空值明确写 `""`；优先级兼容 `Infinity`、`-Infinity` 和未知值。

## C：标题与指令表达

- 标题缺失、直接使用处理函数名或有明确正则残片，扣 5 分。英文标题本身、标题长度或未加插件前缀不自动扣分。
- 指令缺失、只有占位符、直接使用函数名或仍待核实，扣 10 分。
- 指令包含明确正则结构，如 `$^`、`\d`、断言或首尾锚点残片，扣 8 分。
- 非文本事件没有说明事件触发形式，扣 5 分。

标题最多扣 5，指令最多扣 10。`#<角色名>面板`、`#<平台名>搜索<关键词>`、链接或事件触发说明均有效。不会仅凭 `ookie`、`lugin` 等子串判断残码。

## D：用途、参数与正文质量

- 用途缺失或仅有无/未知等空值，扣 15；用途待核实或只剩空泛模板，扣 10；本小项取较重项。
- 参数缺失或仅有未知/不详等空值，扣 10；含义待核实或只有通用占位符，扣 5；本小项取较重项。`参数：无`有效，有意义的参数模板也有效。

仅统计指令、用途、参数、示例的值及它们之间的换行，不含字段标签和五项采集事实。按 Unicode 字符数计算，无最低字数要求。

| 说明文字长度 | 扣分 |
| --- | ---: |
| ≤350 | 0 |
| 351–550 | 1 |
| 551–1000 | 3 |
| 1001–2000 | 5 |
| >2000 | 8 |

重复说明及已知通用套话每类扣 1，最多 3。重复与长度膨胀取较重项，不叠加。D 项合计最多扣 25。

## E：示例可靠性与一致性

可靠性最多扣 10，同一条目取最严重的一项：

- 缺少具体示例、规范的待核实兜底、占位符或函数名伪指令、任意具体示例不匹配原正则、验证未完成，各扣 10。
- 没有上述问题但示例超过八条，扣 2。
- 合法非文本事件写明“无（通过实际事件触发）”即可，不要求编造文本示例，不执行文本样本匹配。

一致性最多扣 10：普通条目建议指令不等于首条正文示例扣 5，原有 examples 与正文数组不同扣 5；事件或待核实条目建议指令不为空扣 5，原有 examples 不为空数组扣 5。原来没有 examples 不要求新增。缺少首条示例时不再额外扣无法核对的一致性分，但明确的错误旧值仍扣分。

普通待核实条目正确留空建议和已有数组时，仅扣可靠性 10 分，其余维度完整可得 90 分；不另叠加“待核实”罚分。

具体链接使用与普通文本相同的原正则及 flags 校验，不受采集器“不自动猜测 URL”的限制。使用宿主本来的匹配语义，不额外添加锚点，每次匹配重置 `lastIndex`，兼容 `g`、`y`。

## 长正则与严重问题上限

| 原始正则长度 | 额外扣分 |
| --- | ---: |
| ≤300 | 0 |
| 301–800 | 1 |
| 801–1500 | 2 |
| 1501–3000 | 3 |
| >3000 | 5 |

按解码后的原值字符数计算，不按 JSON 转义后的显示长度计算。仅旧正文仍包含 regexp 字段时对长正则扣少量分，元数据中的长正则不扣分；不因它撑长整篇再重复扣分。2000/6000 字符仍是整理目标，不是评分一票否决线。整理模型不得修改原正则以提高分数，优化应在源插件完成并重新采集。

明确永不匹配的规则最终最高 40 分。正则无法编译、正文正则与元数据不一致，或任意可靠具体示例确定不匹配，最终最高 60 分；多个上限取最低。疑似、待核实、预算不足、验证超时不触发上限。

## 自动判定与原稿边界

程序只处罚可由当前资料确定的问题。用途真实性、参数业务含义、同名消歧、多动作是否遗漏、负向断言词是否被错误解释，以及某个内部标识是否确实不能作为用户入口，不能仅凭函数名或 `|` 数量证明。缺少证据时不自动猜测扣分；本版本没有新增人工评分标注入口。疑似内部标识自动扣 5 分，不冒充已确认内部规则的更重处罚。

目前只读取导入后的文档，没有同时提供本次采集原稿；结果明确标注 `originalComparison: not-provided`，不声称已对照 ID、数量、顺序或只读元数据是否被模型修改。数据库旧版本也不充当本次采集原稿。不会为评分新增 sourceHash 或重复元数据字段。

非法 JSON、重复/无效 ID、必要字段类型错误及实际大小上限仍由[导入校验](command-knowledge.md)处理，不能用高分抵消；低分本身不阻止导入。

## 安全、缓存与数据影响

原正则编译与样本匹配在隔离的 VM 上下文中运行，单次总时限 15ms。最多校验 64 个去重样本，单个最多 8192 个 UTF-16 单元，样本合计最多 32768，原正则最多 65000；超出预算或超时均为未完成验证，不当作语法无效或不匹配。缓存不包含外部代码，不调用处理函数或模型。

按规则版本、保存的标题、正文和相关原始元数据计算内存缓存键；使用次数、启停和推荐派生值不影响分数。启动、导入或维护后预热，每约 8ms 让出执行机会；单次前台预热的正则工作预算为 1 秒，剩余条目在后台逐条校验并让出执行机会，完成后刷新可读到更新的分数，不会因调度预算留下永久扣分。真正超出样本/长度限制或正则超时的结果仍明确扣分。文档修订后重新计算，缓存不修改 SQLite。预热后翻页、排序、审计和启停复用结果，进程重启会重新计算。

评分不改变正文、历史、启停、授权、召回排序、向量或索引任务，不需要重建已有向量。
