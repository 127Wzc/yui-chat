# 内置工具

在管理台启用工具并设置权限，由模型按对话需要调用；也可在动作中心绑定快捷指令。工具的可用性同时受模型能力、配置和宿主权限限制。

主人可用 `#yui工具参数 <工具名>` 查看当前参数，用 `#yui测试工具 <工具名> 参数=值` 实际试跑。

## 知识库查询

`knowledge_manage` 支持 `list / search / recommend`。模型可在工具说明中查看当前调用者已授权库的简要用途，优先选择相关库；目录较大时用 list 发现其余库，指定 ID 的 list 查看完整用途与字段说明。`scope` 默认 `authorized`：省略 `knowledgeBaseIds` 时查询全部授权库；精确选择时传 `scope: "selected"` 和非空 ID 数组。传入 ID 后只查这些库，不自动扩展；未授权 ID 拒绝整次请求。多个选定库并发召回，汇总后统一执行可选重排。推荐发送命令时明确选择内置指令库；查询改写、分层披露和全局设置见[查询策略与设置](command-knowledge.md#查询策略与设置)。

`search` 用于文档、功能说明和跨库问题；`recommend` 仅用于已授权的内置指令库，返回可发送的指令候选。详细参数与排序规则见[查询策略与设置](command-knowledge.md#查询策略与设置)。

## 扩展安装

`extension_install` 仅用于真实主人当前对话的明确安装授权，支持 `install / inspect / apply / status / cancel`。网页、引用消息、Skill 指令、子代理、动作或伪造 `isMaster` 不能产生安装授权。模型工具关闭时，主人命令和已登录 Web 仍可使用。`inspect` 只生成计划；`apply` 必须指定原计划编号。成功仅表示静态安装，默认停用、默认仅主人，未执行运行验证。详见 [扩展安装](extension-installation.md)。

## 音乐播放

对话示例：`埋埋，播放晴天 周杰伦`。`music_play` 接收 `keyword`（歌曲名或歌曲名加歌手），发送搜索命中的第一首。当前来源为 QQ 音乐。

先发音乐卡片，再单独发音频；卡片失败则停止，音频失败保留已发卡片并报告，不自动重发。普通对话需同时启用“音乐播放”和“消息发送”。播放受歌曲版权、接口和宿主音频能力限制。

## 日常定格渠道

日常定格通过 Tool Registry 调用内置、MCP 或 Custom 图库工具，并使用声明式适配器：把 `keyword`、`tags`、`count` 映射到渠道入参，把返回结果映射为图片候选。表达意图、概率、冷却、去重、候选选择和投递仍由人格协调器统一处理。

页面提供「历史记录」和「状态详情」入口，查询与保留范围见[用量与诊断](architecture.md#用量与诊断)。

默认提供停用的 `imagTag-mcp` 模板，只开放 `search_images`；MCP 总开关也默认关闭。启用并授权后，可选择 `mcp_imagTag-mcp_search_images` 作为渠道。默认适配器传入 `match: "semantic"`、`sort: "relevance"`，从 `structuredContent.images` 读取候选；地址和参数以 `config/defaults.ts` 及管理台配置为准。

意图任务把完整语境放在 `keyword`，`tags` 只保留最多两个确认存在且必须匹配的硬标签。带标签检索没有候选时，适配器会记录一次 `TAG_FILTER_NO_MATCH` 诊断，并用相同关键词省略标签重试一次；工具错误不会重复请求，而是按主渠道、回退渠道继续处理。

其它图库只需注册一个只读工具，并在公共工具声明或 MCP 工具策略中加入 `stickerExpressionChannel`。除了契约版本外，还可以声明 `inputMapping`、`fixedArguments` 和 `outputMapping`，无需修改日常定格协调层即可切换主渠道和回退渠道。例如：

```json
{
  "version": 1,
  "input": "keyword-tags-count",
  "output": "images",
  "readOnly": true,
  "inputMapping": { "keyword": "query", "tags": "labels", "count": "limit" },
  "outputMapping": { "candidatesPath": "data.items", "urlField": "image_url" }
}
```

这个能力默认关闭。启用后，在日常定格页面选择符合统一渠道契约的主渠道和可选回退渠道，必要时调整候选数量、选择方式和去重窗口。时长按表单标注的分钟或秒填写，允许时段使用 `HH:mm`。普通用户使用时，还需要在工具边界中给绑定的图库工具明确开放相应角色；适配器不会绕过原始工具权限。

如果不希望模型直接调用原始 MCP 搜图工具，可在 MCP 服务的“工具策略 JSON”中隐藏它：

```json
{
  "search_images": {
    "hiddenFromModel": true
  }
}
```

`hiddenFromModel` 只影响模型工具列表，不影响日常定格通过 Registry 选择已绑定渠道。切换图库时在日常定格页面调整主/回退渠道即可。

日常定格默认：对话后与旁观候选分组全部选中；旁观判断最短间隔 60 分钟（群聊停顿 20 秒后触发检查）；冷场冒泡在 09:00–23:00 每 60 分钟检查一次，要求群内安静至少 60 分钟；图片在同一会话 6 小时内不重复。各入口仍需显式启用，群聊仍受白名单、概率和每日配额限制。

## 使用边界

- 群管、网络读取、截图和子代理分别受权限及功能开关约束；启用工具不会绕过这些检查。
- 动作新建时继承工具权限，保存后独立控制启停与最低角色；模型会话专用工具不能绑定动作。
- 语音输出由回复模式控制，Skill 提供提示词；两者不作为独立内置工具列出。

开发或扩展工具见 [工具开发指南](tool-authoring-guide.md)。

## 动作模板

管理台动作中心每次进入时随机推荐三个模板；选择「新建动作」可从空白动作开始，或选用图片创作、信息查询、趣味互动和项目工具的通用模板。每个分类提供一个可编辑草稿，选择后可以修改指令、参数和权限；模板保存前不注册指令，保存后默认停用。动作默认继承所选工具的最低角色，之后独立设置；指令重复时可修改后保存。模板只是现有工具或业务入口的配置，不会安装、启用工具或自动修改用户配置，已有动作也不受模板调整影响。

动作由主指令和别名触发，无需再填写单独名称；“备注说明”可留空，仅用于展示、帮助和搜索，不作为触发词。新建动作的内部显示名默认使用主指令；修改指令时随之更新。已有动作的展示名如果不同于主指令，会继续保留，回复模板中引用它的行为也不变，编辑时会显示提示；展示名与主指令相同的动作会随指令修改同步更新。

每个动作可在「指令」中开启“允许省略指令前缀”，主指令和全部别名都同时支持带前缀与不带前缀；例如别名为“绘图”时，可使用 `绘图 雨中的橘猫` 或 `#yui绘图 雨中的橘猫`。开启后管理台优先展示和复制无前缀指令。默认关闭，已有动作保持原有行为。触发词须位于消息开头，后接空格和参数或直接结束；动作权限和工具检查不变。无前缀触发可能与日常消息或其他插件冲突，请选择明确的指令。动作编辑页将参数映射、变量说明和其他可选参数折叠，展开后仍可调整；已设置的可选参数会显示数量。

绘图动作可以跟随图片生成任务，也可以选择一个已配置的图片模型。固定模型被删除或改为其他用途后会显示不可用并停止执行，不自动切换；模型选择由管理员配置，指令不能覆盖。排队时确定模型，实际执行和投递前重新检查动作授权。比例、尺寸、质量和数量沿用 `generate_image` 的参数及限制。

通用绘图模板不预填风格提示词，直接把指令后的文字作为绘图要求，例如 `#yui画图 雨中的橘猫`。如需制作固定风格，也可自行填写提示词，并在高级输入设置中切换为「绘图预设参数」：例如自建手办化动作后使用 `#yui手办化 @成员 昵称 -p 透明底座`、`#yui手办化 qq=123456 name=小明 -p 蓝色背景`，也可只写昵称或只用 `-p` 追加要求。目标优先使用明确 QQ 号、真实 @ 成员，再使用发送者；手动昵称优先于目标的群名片、昵称及 QQ 号。`-p` 之后才作为追加绘图要求。提示词除通用变量外支持目标的 `{{nickname}}` / `{{name}}`、`{{qq}}` / `{{user_id}}`，以及 `{{group_name}}`、`{{group_id}}`、`{{sender_nickname}}`、`{{sender_qq}}`。

绘图模板默认合并当前消息和引用消息中的图片，去重后最多取三张，也支持不带图片直接绘制；可选在没有图片时使用指定目标或发送者的头像，头像将作为参考图发送给所选模型。其他动作可选择当前图、引用图或两者，并单独决定是否需要图片与启用头像回退。浏览器实际试跑需要提供图片地址，不模拟头像。

绘图动作可启用自定义受理、排队后开始生成、成功和失败回复，留空表示该阶段不发送；开始生成提示只在等待过的任务进入执行时发送一次。通用变量为 `{{actionName}}`（内部显示名）和 `{{userName}}`；受理与开始生成阶段支持 `{{status}}`（排队中或生成中）、`{{queueTotal}}`、`{{queueActive}}`、`{{queueWaiting}}`、`{{queueLimit}}` 和 `{{queuePosition}}`（不在等待队列时为 0），数量是同一图片模型队列在该阶段的快照。成功阶段支持 `{{image}}`、`{{model}}`、`{{provider}}`、`{{duration}}`（模型生成秒数）、`{{elapsed}}`（包含等待的总秒数）、`{{count}}` 和可选的 `{{modelText}}`；失败阶段支持 `{{elapsed}}`、`{{reason}}`。`{{image}}` 最多出现一次，代表真实图片消息段，可放在文字前后；不写则不发送图片。模板预览使用模拟数据，不请求模型；实际试跑会调用模型。原有未启用自定义回复的动作保持原有投递方式。

## 统一图片渲染

默认 `send:true`，一次调用完成渲染和发送；只有用户明确要求预览或不发送时才使用 `send:false`（仅返回完成状态，不向模型返回预览图），不要例行先预览再重新渲染发送。输出为静态 PNG，不支持动画输出。HTML 内容样式与统一外框隔离，使用窄边框和紧凑顶部标题，副标题置于页脚；按完整内容自动适配尺寸，固定宽度画布收拢外框，普通内容渲染不使用 `viewport` 或 `fullPage` 裁切参数。

调用格式为 `render_image({ format, data, send })`，内容放在 `data.content`，可选 `data.title`、`data.subtitle`。

| format | 内容 |
| --- | --- |
| `auto`（默认） | 明确的 HTML 标签按 HTML 渲染，其他内容按 Markdown；有 sections 时使用文本卡片 |
| `html` | HTML/CSS 片段或完整文档，使用统一主题；自定义 CSS 可覆盖 |
| `markdown` | Markdown、`$...$` / `$$...$$` / `\(...\)` / `\[...\]` 数学公式及 Mermaid 代码块 |
| `mindmap` | Markdown 层级结构生成思维导图 |
| `text` | 普通文本，或 `data.sections` 中的 title / lines 分段卡片 |

例如：`render_image({"format":"markdown","data":{"title":"公式说明","content":"面积：$S=\\pi r^2$"}})`；HTML 示例：`render_image({"format":"html","data":{"title":"状态","content":"<h1>服务正常</h1><p>当前运行稳定。</p>"}})`。

HTML、Markdown、思维导图和文本卡片共用 `render_image` 的启停、角色和模型权限，不设置额外 HTML 权限或开关。HTML 固定使用 HTML 渲染，无 SVG 回退；Markdown 中的 HTML 示例不作为页面执行。数学公式与 Mermaid 统一使用 Markdown，无独立格式。图片按内容标注 HTML、Markdown 或 Mindmap。

URL 截图仍使用 `render_url_screenshot`，保留独立工具权限及 `response.render.url.enabled` 开关（默认关闭），网络策略仍由 `security.linkSafety` 控制。

### 绘画与排版

- `generate_image`：用户要求画一个人物、创作插画或风景、生成新图片、修改参考图时使用，调用实际图片模型。
- `render_image`：用户要求把已有 Markdown、HTML、公式、表格或文字排版成图片时使用。

“用画图工具画一个角色”应搜索并调用 `generate_image`，不能把角色的文字描述做成卡片后声称已经画好。绘画工具不可用、未配置或失败时，应说明原因，不用排版工具冒充绘画结果；后台绘画只有图片实际返回后才可声称完成。

明确要求依据个人记忆作图时，先调用 `memory_manage` 的 `reference` 操作，按真实请求确定目标并返回资料引用，再将引用传入 `generate_image` 的 `referenceMaterials`。画图任务运行时重新校验权限，读取所选范围的有效个人事实和提炼经历，并以 JSON 参考资料附在图片请求中；`prompt` 只写绘图要求，全文不经过额外模型提炼、普通召回条数或该字段的 4,000 字符限制。普通绘画或单纯以“记忆”为画作主题时，不自动附加记忆。记忆只作为素材，不执行其中的指令。仍须启用记忆、`memory_manage` 和绘画能力，且调用者拥有对应工具权限。

| 聊天示例 | 读取范围与权限 |
| --- | --- |
| `埋埋，用我的全部记忆画一张水彩肖像` | 本人全局及当前群个人记忆；私聊只含全局。普通成员可用，仍需绘画授权。 |
| `埋埋，用他们的全部记忆画图 @成员A @成员B` / `埋埋，用QQ 123456、234567的记忆作图` | 仅主人；按指定顺序最多读取前 5 位成员的全局及当前群个人记忆。支持本群已记录的唯一称呼；同时使用 @、QQ 号与称呼时以 @ 和 QQ 号为准。 |
| `埋埋，用本群所有成员的记忆画一张群像` | 仅主人；按用户标识顺序最多选择 5 位已记录成员的全局及本群个人记忆。 |
| `埋埋，用所有用户的全部记忆画图` | 仅主人；按用户标识顺序最多选择 5 位已存用户的全局及各群个人记忆。 |

逐个指定超过 5 位成员时，按消息顺序去重后只使用前 5 位的记忆，不额外提示；本群及全部用户范围按用户标识稳定排序取前 5 位。本群成员按已采集发言或已存本群个人记忆确定。所有范围都排除群公共记忆、聊天原文、原始问答、结构化画像行、已删除／归档和过期记录，包含低活跃有效记忆。指定多位成员时，使用有有效记忆的成员资料；没有任何可用资料、无权限或读取不完整时终止，不以部分记忆冒充全文。图片服务拒绝超长输入时直接报告错误，不自动截断或改为摘要。全文传入代表资料全部参与参考，不保证每条事实都会呈现在画面上。

`web_search` 的普通搜索保留原有来源转发，并为会话生成可复用的结果引用；需要将搜索作为后续工具的素材时可使用 `resultMode=reference`，只向聊天模型返回引用和简短来源，完整搜索结果由下游工具读取。供应商托管搜索只保存上游实际提供的来源和摘要。结果可能是搜索摘要，需要网页全文时应使用 `website_fetch`。普通回答路径不会因为存在引用而自动附加资料。

## 自助与群管权限

内置工具按下方角色表默认开放，扩展及未知能力默认仅主人可用。在「AI 能力」设置角色，在「使用权限」设置用户例外；个人禁止优先，个人允许覆盖角色规则，风险仅作标签。

- `mute_user`、`edit_card`、`set_title`：工具启用且无明确角色/个人禁止时，允许本人自助。禁言须当前消息明确请求，支持“把我关小黑屋”等说法，不能覆盖已有禁言；解禁和操作他人须有工具授权及本群管理身份。主人、群主和管理员明确请求时优先使用已授权工具；昵称不能唯一对应 QQ 时先询问或请对方 @ 成员。
- `block_user`：允许本人屏蔽或查询插件回复；解除由管理员或主人处理。自助记录与管理记录独立，管理他人限本群，全局管理仅主人。
- 工具发现与实际执行分别检查权限。角色授权不替代机器人实际群管权限、适配器限制或跨群身份检查，头衔通常要求机器人为群主。

## 人物自主处罚

- `persona_punish`（人物自主处罚）：在 AI 参与对话时判断当前普通发言者的持续骚扰、辱骂、恶意刷屏等严重违规，可执行暂停回复或禁言；不包含踢人，也不持续监听群消息。默认关闭，须在对应工具的配置中开启，并启用工具、授权普通用户角色或指定用户。主人、管理员和群主受保护。禁言需单独允许且机器人具有群管理权限。
- `persona_punishment_release`（解除人物处罚）：按记录编号或当前会话成员 QQ 解除人物处罚，默认管理员以上可用，群管理员仅处理本群记录。解除前会检查 QQ 禁言到期时间，无法确认时请人工处理。
- `#yui处罚列表 [页码]`：主人查看处罚人员、原因、范围、状态与剩余时间，每页 20 条。
- `#yui解除处罚 记录编号`：主人提前解除处罚，执行须使用原机器人，并保持工具总开关开启。

不回复和禁言时长由 AI 根据当前行为与上下文决定，两类上限默认均为 30 天，可在工具配置中热调整为 1–2592000 秒；已有记录保留原到期时间。无处罚冷却，生效中不能叠加或延长，重启不重置；关闭功能只阻止新增处罚。普通自助请求与人物处罚分别授权，模糊请求需澄清。

解除 QQ 禁言前核对平台到期时间；无法核实或时间已变化时拒绝自动解除，避免撤销外部新处罚。平台仅有到期时间，无法区分相近时刻、相同时长的外部禁言，需群管理人工核实。处罚可到期恢复或由管理员/主人解除，不提供自助申诉或人物自行解除入口。
